Overview

The Form Skate agent is a coding agent that lives in one tile of the workbench and works through a single tool, eval, which runs JavaScript in the page with the workbench's lab API in scope. Every step shows up as a collapsible block with its code, its time and its result, and the files are snapshotted before each step so the person can revert it.

Use this system to build the same kind of agent into another tool, to extend this one, or to write the way it writes. Start with the section that matches the job:

  • How the agent works: the turn, the tool rounds, what the model receives, step records, revert, threads and storage.
  • The eval tool: the tool schema, how code runs, every name in the scope, the YAML result format, the Read-only guard.
  • Modes and permissions: Auto, Ask and Read-only; Model and Thinking; what the panel says when Claude is unavailable or a turn fails.
  • Patterns: how the agent should work, with do and don't examples.
  • Voice: how its answers read.
  • The system prompt: the instructions and the context block, quoted in full.
  • lab: links: the links an answer can carry into the workbench.
  • Extending the agent: recipes for a new scope function, link action, mode or context line.

Build an agent like this one

  1. Give the model one tool. Name it eval; its input is { code }, the body of an async function. Run the code against a scope object made for the purpose and return the value as YAML text. Do not add a tool per action: with one tool the model writes the loop (fifteen tests, two fields each, a comparison) and the person reads it.
  2. Build the scope from the app's public API. Here it is labScope(host) from app/host.js, plus console, log and lab; the host object itself is deleted from the scope. The scope is documented in the same Reference the person reads, and the whole Reference is appended to the instructions, so the agent's API and the person's are one document.
  3. Bound every step. Race the code against eval-timeout (25 s), cut the result at result-cut (9,000 characters) and tell the model how to return less.
  4. Snapshot before, offer revert after. Copy the files before each step. When the step changed a file, show revert files to before this step.
  5. Send instructions once and context every time. The instructions and the Reference ride on the first user turn; a [context] block of live state rides on the latest. Earlier steps go back to the model as one line each.
  6. Let the person choose how much to approve. Auto runs each step, Ask waits for Run this step or Decline, Read-only makes every editing path throw.
  7. Plan for absence. When claude.use('sample') gives null, show the off banner, disable Send and the suggestions, and keep the rest of the app working. Map every error code to one plain sentence.

How the agent behaves

  • Look before changing: files.grep, files.read, describe, inspect.
  • Change with files.edit on exact, unique text; then run() and read { ok, errors }.
  • Verify in a fresh world with test(), before and after, and report the numbers the run returned.
  • Sweep everything that shares the changed code, not only the trick that was named.
  • Say which world a number came from: live params, build options and the stage's history do not reach a headless test.
  • Answer in a few short paragraphs of Markdown, naming files and lines, with lab: links the person can click.

How it looks

The panel follows the workbench's Kiln rules (Form Skate Workbench, linked below).

  • The ground is bg, text is ink, secondary text is ink-2. One family, ui (Arial), in two weights, 400 and 700. Sizes come from fs-xs (10.5px), fs-s (12px) and fs-m (13px) only.
  • Structure is drawn with line-1 rules: hair for controls and boxes, rule for the quietest dividers. No shadows and no rounded corners (radius-0). The only tinted grounds are code-bg behind code and the textarea, and fill behind inline code.
  • accent red marks what needs the person or what failed: a step waiting for approval, a failed step, the label of a turn that errored, Stop, the small marker after a lab: link, and the => arrow in code. Never use it as decoration or as a fill behind text.
  • Pressed and primary controls invert: an ink fill with bg text (the pressed segment, Send, Run this step).
  • Show state by form as well as colour. A step's square dot (dot-step) blinks while the step runs, turns accent and keeps blinking while it waits, stays accent when the step failed; a reverted step drops to opacity-reverted with its first line struck through; the turn being written shows Thinking or Working with a blinking square (dot-thinking).
  • The only motion is the blink: keyframes bl (50% { opacity: 0 }), 0.8 s, steps(2). Nothing slides or fades.
  • Code is in the code family at 10.5px. Results are YAML, never JSON.
  • Copy is plain and short. The person is You, the model is Agent. Controls are named Mode, Model and Thinking; their options Auto, Ask, Read-only; Fast, Balanced, Deep; Auto, Low, Med, High. Buttons are verbs: Send, Stop, Run this step, Decline, + New.

Using the components

components/bundle.css is the panel's own CSS; colours and sizes resolve through this system's tokens. Each component's guidelines give the exact markup. There is no JavaScript bundle: the app renders this markup from React, but nothing here depends on React, and the previews are static renditions with real content from the app (the step results in them were produced by running the code shown).

The other Form Skate systems

  • Form Skate Workbench: the Kiln shell around this panel, its tokens, controls, editor, reading views and the guide to writing a book section.
  • Form Skate Stage: the drafting-sheet stage the agent's runs play out on.

extending.md

Extending the agent

Four changes cover most needs. Each touches the scope or the view in one place and the documentation the model reads in another, because the Reference is part of the instructions.

Add a scope function

  1. Add it to the object labScope(host) returns in app/host.js. Return small plain data: numbers rounded, ids as strings, no runtime objects. yaml() will print whatever you return, and the model pays for every character.
  2. Throw an Error with a message that says how to fix the call, as files.edit does: edit: text occurs 3 times in skate/motors.js; include more context so it is unique.
  3. If it changes code, notes or params, guard it in Read-only mode: add its name to READONLY in app/ui/agent.jsx (or, for a method on game, to the pattern in the guard call).
  4. Document it in content/reference.md under "The agent's eval scope". The Reference is appended to the instructions, so the model learns it on the next send; the person reads the same line in the Reference tab.
// an example, not in the library: a small read-only helper inside labScope's api object in app/host.js
lastTrick: () => { const e = rt().events.list({ type: 'trick', last: 1 })[0]; return e ? { t: +e.t.toFixed(3), name: e.data.name, landed: e.data.landed, score: e.data.score } : null; },

Add a lab: link action

  1. Add a case to the switch in Host.link (app/host.js). Read parameters from q, act, call this.focus({ view }) to bring the right view forward, and return true; on a bad target, this.toast('no … ' + id, true) and return false.
  2. List it in the Reference's "lab: links" section, so the agent can write it, and in the book's appendix of links for readers.
  3. Add a matching case to test/linkcheck.js, which test/links.js and the book check use; an action it does not know is reported as unknown action. The case returns null for a good link or a short reason for a bad one.

Add a mode

  1. Add an option to the Mode Seg in AgentView: { value, label, title }, where title is the tooltip.
  2. Branch on S.settings.mode where the step runs: in execute for something that happens before a step (as Ask waits for approval), or in runEval for a different scope (as Read-only swaps in throwing functions).
  3. Add its words to the composer's meta line.
  4. Add one sentence to the instructions telling the model what the mode means for it, as the line for Ask and Read-only does.

Add a line to the context block

Add a lines.push(…) to context(host) in app/ui/agent.jsx. Keep it to one line of live state the model cannot cheaply get with eval, and leave it out when it does not apply, as the diagnostics and pinned-trace lines do. Every line is sent with every message.

Change a limit

limit where
25 s per step the setTimeout in runEval
9,000 characters per result if (out.length > 9000) in runEval
3,000 characters per stored result, 30 turns per thread persist()
100 and 160 characters per earlier step toTurns()
5 decimals, 60 items, 64 numbers, 80 keys, 5 levels yaml()
8 diagnostics, 5 tricks context()

Keep one tool

The design rests on a single eval. A second page tool is possible (the tools array takes several, up to the limit the capability reports), but each one needs its own schema and description, and the model cannot combine them in one loop the way it combines scope functions in one step. Prefer a new scope function.

how-the-agent-works.md

How the agent works

The agent is one React view, AgentView in app/ui/agent.jsx, shown in the workbench's Agent tab. It keeps its threads in a module-level object, asks the page's sample capability for Claude, and gives Claude one page function, eval. Everything below is what that file does.

The parts

part where what it does
S agent.jsx:9 { threads, active, settings }, read from browser storage at load; settings default to { mode: 'auto', tier: 'default', effort: '' }
persist() agent.jsx:11 writes threads (trimmed), the active thread and the settings back to storage
getSample() agent.jsx:13 calls window.claude.use('sample') once and remembers the promise; null when the capability is missing or throws
yaml() agent.jsx:16 turns any value into the YAML text the model reads
runEval() agent.jsx:43 builds the scope, runs one step's code, formats the result
instructions() agent.jsx:73 the instructions, ending with the whole Reference
context() agent.jsx:88 the [context] block of live state
toTurns() agent.jsx:101 the thread as the turn list sample() takes
AgentView agent.jsx:118 the panel: threads, settings, log, composer; send, revert, newThread, closeThread

One turn

send(text) (agent.jsx:127) runs a whole turn:

  1. It ignores empty text and does nothing while a turn is running.
  2. It awaits getSample(). With no capability it sets the off message Claude is not available here, so the agent is off. Everything else in the workbench works. and stops.
  3. It appends the user turn and, if the thread is still called New thread, titles it with the first 32 characters of the text.
  4. It appends an agent turn { role: 'agent', text: '', steps: [], pending: true }, clears the composer, marks the panel busy and saves.
  5. It makes a fresh AbortController; Stop calls abort() on it.
  6. It defines the eval tool (see the eval tool section) and calls sample:
// app/ui/agent.jsx:157–161
const turns = toTurns(host, th);
const opts = { signal: ctl.current.signal, modelTier: S.settings.tier, tools: [evalTool], onText: ({ text }) => { turn.text = text; re(); } };
if (S.settings.effort) opts.effort = S.settings.effort;
const res = await sample(turns, opts);
turn.text = res.text; if (res.truncated) turn.note = 'The answer hit the length limit.';
  1. onText assigns the whole answer so far to the turn on every call, so the answer streams into the log.
  2. A rejection becomes a one-line note on the turn (modes and permissions lists each one). Any text that had already streamed is kept, except after refused, where it is cleared.
  3. The turn stops pending, the panel stops being busy, and the thread is saved.

The loop belongs to the capability

The view has no loop of its own and no step counter. One sample() call carries the whole turn: Claude calls eval, the page runs execute, the result goes back, and Claude calls eval again or writes its answer. The sample capability makes these rounds and, per its contract, allows a handful of them and makes the last one an answer. Each round re-reads everything so far, which is one more reason to keep results small. Stop rejects the call with cancelled, aborts a running execute through its context.signal, and makes no further round; what the steps already did stays done.

What the model receives

toTurns (agent.jsx:101–114) rebuilds the conversation every turn:

  • A user turn is sent as its text.
  • An agent turn is sent as one line per step, then its answer (or (no answer)): [eval] <first line of code, up to 100 characters> → <result with whitespace collapsed, up to 160 characters>, with , later reverted after eval when the person reverted that step.
  • Trailing agent turns are dropped, so the list ends on a user turn.
  • The first user turn is prefixed with the instructions and a --- line; the last user turn is prefixed with the context block. Two turns of the same role in a row are merged.

On the first message of a thread both prefixes land on the same turn, so it reads: context block, instructions, Reference, ---, the person's words. In B-01 that first turn is 17,619 characters. Its context block, captured from a real run:

[context]
preset: B-01 Flatground (Basics) — The whole game, as the library ships it: a lot, a funbox, a board, a rider, fifteen tricks.
world: t = 3.86 s, running at 1×, driver autopilot
build: ok (16 systems, 15 signals, 42 states)
files: depth-order.js, experiments.js, main.js, rigid.js, skate/assist.js, skate/board.js, skate/controls.js, skate/figure.js, skate/index.js, skate/motors.js, skate/recognizer.js, skate/rider.js, skate/terrain.js (* edited)
pinned traces: recognizer/height, recognizer/flipTurns, recognizer/shoveTurns, recognizer/wrapTurns
[/context]

When they apply, the block also lists up to eight warnings and errors with file:line, the system that stopped the runtime, the node selected in the Graph, and the last five tricks with their flip, shove and air. A failed build reads build: FAILS — <message>.

So the model's memory is uneven: earlier answers come back whole, earlier step results only as a 160-character fragment. A measurement the agent did not write into its answer has to be measured again.

A step

execute (agent.jsx:139–154) creates one step record per call:

const step = { code, result: null, running: true, ms: 0, snapshot: { files: Object.assign({}, host.files) } };
field meaning
code the code Claude sent
running true until the code returns or is declined
asking, resolve set in Ask mode while the step waits for the person
result the YAML text the model received (or The person declined this step.)
error the code threw, timed out, or was declined
ms how long runEval took
snapshot.files a copy of every file before the step
changed any file differs from the snapshot, or one was deleted
reverted the person reverted this step or an earlier one in the turn

The panel re-renders on every change, so a step appears with a blinking dot as soon as Claude calls it and fills in when it returns.

Revert

// app/ui/agent.jsx:174–179
const revert = (turn, i) => {
  const s = turn.steps[i]; if (!s.snapshot) { host.toast('This step’s snapshot is gone (reloaded page)', true); return; }
  host.files = Object.assign({}, s.snapshot.files); host.saveEdits();
  for (let j = i; j < turn.steps.length; j++) turn.steps[j].reverted = true;
  host.build({}); host.toast('Reverted the files to before that step and rebuilt'); re(); persist();
};

Revert restores files only. A param changed with setParam stays changed, and the live world keeps whatever the steps did to it. The link shows only on a step that changed files and still has its snapshot.

Threads and storage

  • Threads sit in a bar above the settings; + New adds { id: 'a' + Date.now().toString(36), title: 'New thread', turns: [] } and is disabled while a turn runs. Closing the last thread leaves a fresh New thread.
  • persist() keeps the last 30 turns of each thread, drops each step's snapshot and resolve, and trims results over 3,000 characters with \n…. So after a reload the revert links are gone.
  • Storage is the browser's localStorage under the prefix formskate.v1.: threads, thread (the active id) and agentSettings. Every read and write is wrapped in try, so the panel works without storage, for that page load only.

Where the person meets it

  • The Agent tab is in every layout, always in the same tile as Code.
  • A lab:ask?q=… link anywhere in the workbench brings the tab forward with the question in the composer. It never sends it.
  • A new thread shows the empty state: one paragraph and up to six requests (the preset's own suggestions, then Explain what happens in one step of this program, phase by phase and Make the kickflip spin faster and check it still lands). Clicking one sends it.
  • The log scrolls to the bottom on every render.
  • The answer is rendered by the workbench's Markdown renderer (render(text, { highlight, toc: false })), the same one that renders notes, docs and the book. A click on a lab: link calls host.link(href).

lab-links.md

lab: links

A lab: link is an ordinary Markdown link whose target starts with lab:. In an agent answer it is how the agent hands the person a place or an action: open this line, pin this trace, play this trick. The same links work in notes, docs, the Reference and the book.

How they render and run

The renderer turns [text](lab:…) into <a href="#" class="lablink" data-lab="lab:…">text</a>. In an answer the link is underlined in ink with an accent underline colour, followed by a small accent ▸ marker (.doc-inline a.lablink::after). A click calls host.link(href).

host.link replaces lab: with lab://x/ and parses the result as a URL: the path is the action, the query holds the parameters, decoded the way a browser decodes a form. Nothing checks a link before it is clicked; a target that does not exist shows a red toast such as no trace …, and an open link whose find text is missing opens the file at line 1.

The actions

action parameters does
open file, then find or line opens a file in Code at a line; prefer find, which survives edits above it
trace (or pin) id, comma-separated pins signals and states in Traces
node (or select) id, optional in selects a node in the Graph and shows its Inspector
trick (or perform) name plays a gesture 0.02 s after the click, as the person's input
param id, optional value sets a param in the running world; without a value, opens it in Params
preset id loads a preset
doc id, optional at opens a shelf doc at a heading's slug
book ch, optional at opens a chapter of the book (P, 1–62, A–F)
view name, optional track sets the stage camera: axo, front, side, plan
overlay name, optional on shows, hides or toggles a stage overlay
speed x sets the time scale
show (or tile) view brings a view forward (agent, code, traces, …)
order name picks a depth-order strategy
exp (or run) name runs an experiment
record optional trick, seconds, replay records a clip headless and replays it
replay, score none replays the current clip; scores its drawing order
reset, build none restarts the world; rebuilds keeping the world
autopilot optional on hands the board to the autopilot, or takes it back
ask q puts a question in the agent's composer; it does not send it

Writing them

The link text says what the click does or where it goes: skate/motors.js:192, play a kickflip, pin the flip turns.

Escape these characters inside a parameter value:

in a value write because
a space a space spaces are allowed and decoded back
& %26 & separates parameters
# %23 # starts a fragment, which is dropped
+ %2B + decodes to a space
% %25 % starts an escape
( and ) at most one balanced pair, or %28 and %29 the renderer finds the end of the link by its parentheses
$ avoid the renderer reads it as the start of inline maths

A link to a file, param, signal, node, gesture or experiment refers to the program that is loaded. An answer is about the loaded preset, so its links resolve; a note that depends on another preset loads it first with a preset link.

In the agent's scope

The agent can follow a link itself with link(href), and open a chapter for the person with book.open(n, at), which is link('lab:book?ch=' + n + (at ? '&at=' + at : '')).

modes-and-permissions.md

Modes and permissions

The settings bar under the threads holds three segmented controls: Mode, Model and Thinking. All three are saved in the browser (agentSettings) and apply to the next step or turn.

Mode

option value tooltip composer meta line what happens to a step
Auto auto runs each step steps run as they come runs at once
Ask ask you approve each step you approve each step opens with its code and waits for Run this step or Decline
Read-only read no edits read-only runs with the guarded scope: editing code, notes or params throws

The instructions tell the model about both restrictive modes: In Ask mode the person approves each eval; in Read-only mode edits are refused: say what you would change instead.

Ask

While a step waits, its box and dot turn accent, the dot blinks, the time slot reads waiting for you, and the box is open so the code can be read before it runs.

  • Run this step resolves the wait with true; the step runs as in Auto.
  • Decline resolves it with false. The step is marked failed with the result The person declined this step., and Claude receives: Declined by the person. Ask what they want instead, or explain the change without running it.
  • Stop aborts the whole call. A waiting step resolves as declined.

Read-only

files.write, files.edit, run, reset, setParam and setNotes throw, and so do game.setParam, game.set, game.add, game.edit and game.reset; lab is the guarded scope too, and game.paramValues comes back as a copy. Code can still drive and knock the live world (perform, step, world.applyImpulse). Present Read-only as protection against an accidental edit, never as a sandbox.

When Claude is not available

On mount the panel asks for the capability once. If it resolves null, the off banner appears above the log and Send and the suggestions are disabled. If a later call fails with one of the codes below, the banner appears with that code's sentence. The rest of the workbench keeps working. The banner always starts with The agent is off here. and then gives one of these:

cause sentence
no capability at load Claude is not available in this view, so the agent cannot run. Everything else in the workbench works.
no capability when sending Claude is not available here, so the agent is off. Everything else in the workbench works.
not_granted Claude is not allowed for this page. You can allow it from the artifact’s permissions.
sampling_disabled Claude is not available for this account.
not_declared This page no longer asks for Claude.
capability_disabled Claude is unavailable in this view.
tools_unavailable This view cannot run the agent’s tool.
capability_removed This app version cannot run the agent.

The same sentence is also left as a note on the turn that failed.

When a turn ends early

Other outcomes become a note under the turn, in ink-2 at fs-xs. A turn with a note and no text gets the error class, and its Agent label turns accent.

outcome note
Stop (cancelled) Stopped.
rate_limited Too many requests just now; try again in a little while.
prompt_too_large The conversation is too long. Start a new thread.
refused Claude declined this request. (Any streamed text is cleared.)
the answer was truncated The answer hit the length limit.
anything else Interrupted: the error's message or code

The panel never retries on its own. Whatever text had streamed before a failure stays on screen, except after refused.

Consent and cost

The page declares the sample capability. The viewer is asked for consent at the first call; a call draws on the viewer's own Claude usage, every tool round is another request, and calls with tools are never cached. That is why the agent runs only when the person presses Send, clicks a suggestion or sends a prepared lab:ask question.

patterns.md

Patterns

These are the working habits the agent's instructions ask for, and the ones Chapter 54 of the book ("Working with the agent") shows by measurement. Each says where it comes from.

Look before you change

Instructions: "Look before you change: files.grep / files.read(path, from, to) to find code; describe(id) / inspect(pattern) for the compiled program."

  • Do: return files.grep('spin = ', 'skate/motors.js');, then read the lines around the hit.
  • Don't: write an edit from memory of what the file probably says.

Edit exact text, then rebuild

Instructions: "Change code with files.edit(path, find, replace) (exact, unique text) rather than rewriting files. Then call run() — the running world keeps its state — and read the result: { ok, errors }."

  • Do: files.edit('skate/motors.js', 'spin = 19 }', 'spin = 21 }'); return run();
  • Don't: files.write a whole file to change one number. When edit throws text occurs N times, add context until the text is unique.

Verify in a fresh world, before and after

Instructions: "Verify with test({ trick: 'kickflip' }) or test({ script, seconds, opts }) — a fresh headless world — and look at tricks / events / failed. Compare before and after when tuning."

A before-and-after pair from test is exact, because the program is deterministic: any difference comes from the edit. Report both numbers.

Keep results small

Instructions: "Keep results small: pick fields, slice arrays."

  • Do: const k = test('kickflip').tricks[0]; return { name: k.name, landed: k.landed, air: k.air, score: k.score };
  • Don't: return test('kickflip'); when two fields are wanted. Every round re-reads every earlier result, and results over 9,000 characters are cut.

Name a measured quantity

Chapter 54.4: "Make the kickflip feel snappier" leaves the agent to decide what snappier means; "make the catch come earlier, measured by the catch event's after" gives it a target and a test. When a request is vague, pick the quantity, say which one, and measure it.

Sweep everything that shares the changed code

Chapter 54.4: the flick motor serves every trick with a flick, so the honest unit to check is the list of gestures. Raising its default spin from 19 to 21 rad/s keeps the kickflip landing (850 → 845 points), and the same sweep finds the change the narrow check misses:

- gesture: varialHeelflip
  before: varial heelflip
  after: laser flip
  score: 2373

"Yes, it still lands" would have been true and misleading. Use query(q => q.systems().where(n => n.reads('flick/spin'))) to find who shares a value.

Say which world a number came from

Chapter 54.5: a headless run is exact, but it can answer a different question from the person's.

  • Live params do not reach test: it builds at the declared defaults. After setParam('flick/spin', 30), test still answers for 19 rad/s.
  • opts replace the preset's build options: test({ trick, opts }) rebuilds through createSkateGame(opts).
  • The stage's world has a history: a gesture pressed in the air or just after a fakie landing behaves differently from the routine test plays from rest.
  • One run is one sample: a margin needs perturbed runs and a rate.

So state the gestures, the starting state, the param values and any perturbation behind a claim like "it still lands".

Measure again rather than remember

Earlier step results come back to the model only as a 160-character fragment. When an earlier table matters, run it again or ask the person to keep it (for example with setNotes).

In Read-only, describe the change

Instructions: "in Read-only mode edits are refused: say what you would change instead." Give the file, the line and the exact replacement, so the person can switch to Auto or Ask and have it applied.

Hand the person the way in

Instructions: "Name files and lines; you may include lab: links, which the person can click." An answer that changed skate/motors.js:192 links to it; an answer about a trick links to playing it. See the lab: links section.

Remember what revert restores

Revert restores files and rebuilds; it does not restore params, and it cannot undo what steps did to the live world. When a step changed a param, say so in the answer.

system-prompt.md

The system prompt

The sample capability has no system prompt the page controls: Claude sees only the turns the page sends. So the agent's instructions travel inside the first user turn of every call, followed by the workbench's whole Reference (content/reference.md, about 15,000 characters), a --- line and the person's first message. The latest user turn is prefixed with the context block. Both are rebuilt on every send, so a thread picks up a changed Reference or a new preset at once.

The instructions, verbatim

From instructions(host) in app/ui/agent.jsx:73–87; the last line, ${host.reference}, is replaced by the Reference.

You are the coding agent inside Form Skate Workbench, an IDE for building a skateboard game from the ground up on @form/core, a small JavaScript simulation framework (things, sites, links, states, derived signals, systems, watches, views). The game's library is a set of editable files (main.js, rigid.js, skate/*.js, experiments.js). The person you are helping sees the code, a live drafting-style stage, traces, events, params and a dataflow graph.

You have one tool, eval: it runs an async JavaScript function body in the page and returns the value (as YAML) plus anything you console.log. Use it to read files, edit them, rebuild, test tricks headlessly, read traces and events, and change params. The scope is described below under "The agent's eval scope". Keep results small: pick fields, slice arrays.

How to work:
- Look before you change: files.grep / files.read(path, from, to) to find code; describe(id) / inspect(pattern) for the compiled program.
- Change code with files.edit(path, find, replace) (exact, unique text) rather than rewriting files. Then call run() — the running world keeps its state — and read the result: { ok, errors }.

The eval tool

eval is the agent's only tool. Claude sends JavaScript; the page runs it with the lab scope and sends back YAML. The model decides what code to send; the page decides what that code can reach.

The schema

// app/ui/agent.jsx:135–138
const evalTool = {
  name: 'eval',
  description: 'Run an async JavaScript function body in the workbench with the lab API in scope (files, run, test, trace, events, inspect, params, setParam, …). Returns the value as YAML plus console.log output. Use `return` to return a value.',
  inputSchema: { type: 'object', properties: { code: { type: 'string', description: 'the body of an async function; return what you want to see' } }, required: ['code'] },
  execute: async ({ code }, c) => { … },
};

execute coerces code to a string, records the step, waits for approval in Ask mode, runs runEval, stores the result on the step and returns the result text to Claude.

How the code runs

// app/ui/agent.jsx:59–68
const names = Object.keys(scope).filter(k => /^[A-Za-z_$][\w$]*$/.test(k));
const t0 = performance.now(); let value, error = null;
try {
  const fn = new Function(...names, '"use strict";\nreturn (async () => {\n' + code + '\n})();\n//# sourceURL=agent-eval.js');
  value = await Promise.race([fn(...names.map(k => scope[k])), new Promise((_, rej) => setTimeout(() => rej(new Error('eval timed out after 25 s')), 25000))]);
} catch (e) { error = e; }
  • Every scope name becomes a parameter of a strict function whose body is an async arrow around the step's code. So the code can await, must return what it wants seen, and its const and let names do not carry over to the next step. Each step gets a new scope object.
  • The race abandons the wait after 25 s with eval timed out after 25 s. It only catches code that awaits: a synchronous loop that never ends blocks the page, because the timer cannot fire.
  • An error comes back as Error: <message> (line N), with N taken from the agent-eval.js frame of the stack. In the current build N is two higher than the line in the step's code: a throw from the first line reports (line 3).
  • Anything passed to console.log or log is collected; strings as they are, other values as one-line YAML. console.warn and console.error add warn: and error: lines.
  • With logs, the result is logs:, the lines, ---, then the value.
  • A result over 9,000 characters is cut, and the model reads … cut (N chars). Return less: pick fields, slice arrays.

Voice

What the instructions ask for

The instructions set the shape of every answer:

Answer in a few short paragraphs of markdown. Name files and lines; you may include lab: links, which the person can click: open, pin, try it, select, doc. Use $…$ for maths.

Physics is in SI units: metres, seconds, kilograms, newtons, radians. The step is 1/120 s with 8 substeps.

So an answer is:

  • A few short paragraphs. Not a report, not a list of everything the steps printed. The steps are already on screen above the answer.
  • Concrete. It names the file and line it changed, the numbers it measured and their units.
  • Linked. Places and actions are lab: links, so the person can go there with one click.
  • Plain Markdown. Bold for the names that matter, inline code for identifiers, a table when there are more than a few numbers to compare, $…$ for maths.

The shape of a good answer

This answer closed the thread in the screenshots. Its numbers are the results of the steps above it.

I raised the flick motor's default spin from 19 to 21 rad/s at skate/motors.js:192 and rebuilt; the running world kept its 37 states and 4 bodies.

Measured in fresh worlds before and after the edit, the kickflip still lands. The catch comes 0.283 s after the flick instead of 0.308 s, the flip stays at 0.988 turns, the air goes from 0.417 to 0.408 s and the score from 850 to 845. Play a kickflip to see it.

The flick motor serves every flip trick, so I also ran all fifteen gestures. One changed name: the varial heelflip is now recognized as a laser flip, worth 2,373 points. Should I look for a rate that keeps it a varial heelflip, or keep 21 rad/s?

  • The first paragraph says what changed, where, and that it was rebuilt.
  • The second gives the measurement that answers the request: before and after, with units, and which world it came from.
  • The third reports what else the change touched and ends with the one decision the person has to make.

Habits

  • Give the answer as a number the person can check: "0.283 s instead of 0.308 s", not "noticeably faster".
  • Say which world: "measured in fresh worlds", "in the live world at flick/spin 30".
  • Keep "it still lands" attached to its conditions: which gestures, from which starting state, at which param values.
  • Say what the run left out when it matters: live params, build options that replace the preset's, the stage's history, a single sample.
  • In Read-only mode, describe the edit you would make instead of saying you cannot.

The panel's own words

The interface speaks the same way: short, literal, no exclamation marks.

  • Empty state: "Ask for a change and the agent edits the library, rebuilds, and tests it headlessly. It works through one tool, eval, with the same API you see in the Reference."

About this export

This folder is a complete copy of the Form Skate Agent design system, exported on 2026-10-29 from https://claude.ai/artifact/4KJ4g867ubqBbVszAeqXWM (version 1793208168-ca1b).

Open index.html in a browser to read it offline: the brand book, every section, the tokens in both themes, each component's live preview beside its guidelines, and the screenshots. The theme button cycles system, light and dark.

path what
README.md the brand book: start here
*.md further sections
